Imagify

imagify.jpeg.ffm

JpegliCodec

Entry point to the jpegli based JPEG codec using Java's Foreign Function & Memory API (JEP 454).

This is the encoder and decoder behind both the ImageIO service providers in imagify.jpeg and the direct calls imagify.ImageWriter and imagify.ImageReader make, so a JPEG written through any of them comes out of the same encoder with the same settings.

The native library is loaded lazily, on first use, and failing to load it is never fatal: the ImageIO service providers of this library then stay inert instead of breaking ImageIO for every other format, and the facade falls back to the JDK's own JPEG support. Use #isAvailable() to find out which of the two a given call will use.

Shared libraries for Windows, macOS and Linux, in both 64 bit flavours, are fetched on first use from the GitHub release the codec's native.properties names, and are cached locally, so installing anything is not required. Should none be available for the current platform — an unsupported one, an unpublished release, a blocked download — a jpegli based one found the usual way is used instead: point the java.library.path system property (or the platform specific PATH / LD_LIBRARY_PATH) at the directory that holds it. 

 java -Djava.library.path=/usr/local/lib -cp ... YourApp

Set -Dimagify.jpeg.bundled=false to ignore the managed library and always look for one installed on the system.

An encode whose source is already a BufferedImage#TYPE_4BYTE_ABGR image hands its own backing array to the shim, which reads it in place, so the pixels are not copied into native memory on the way in. Anything else is converted to that layout once, through the shared AbgrPixels.

The pixels are always delivered as a BufferedImage#TYPE_4BYTE_ABGR image, whose banks are the very A, B, G, R layout the shim fills in. The alpha channel is fully opaque, because a JPEG cannot carry a real one; it is left opaque rather than composited over a background of this library's choosing, which would quietly change every pixel the caller goes on to compare.

Encodes an image as a JPEG.

A quality below 1 is raised to 1 and one above 100 is lowered to 100, which is what jpeg_set_quality does with them. The ImageIO compression quality is a 0.0 to 1.0 value, so a caller that asks for the smallest possible file asks for 0, and quietly failing on it would turn a legal request into an exception.

The alpha channel is discarded, since a JPEG cannot store one. An image with transparency is therefore written against whatever colour sits behind it rather than losing the picture; a caller that needs the picture has to flatten it first.

An image already in BufferedImage#TYPE_4BYTE_ABGR hands its own backing array to the shim, which reads it where it lies; every other layout is converted to that one first.
