BufferedImageTransform

Pixel rearrangement operations on a single BufferedImage: cropping, rotating and flipping.

Every operation returns a Function that produces a new image of BufferedImage#TYPE_INT_ARGB and leaves the source untouched. That is the same normalisation BufferedImageResize applies, so the result of one of these can be handed straight to the other, and a frame of a FrameSequence can be moved around without its neighbours noticing a difference.

Rotating by a multiple of 90 degrees moves whole pixels and is therefore exact. Any other angle has to resample, and of the ResizeAlgorithms only ResizeAlgorithm#NEAREST and ResizeAlgorithm#BILINEAR have an equivalent in Java2D, so the remaining algorithms resample bilinearly instead. Angles outside a multiple of 90 degrees keep the original canvas and clip the corners, which is what rotating a photograph usually means; the right angles swap the width and the height instead.

Usage:


 Function<BufferedImage, BufferedImage> crop = BufferedImageTransform.crop(0, 0, 32, 32);
 BufferedImage icon = crop.apply(sheet);
 Function<BufferedImage, BufferedImage> rotate = BufferedImageTransform.rotate(photo, -90);
 BufferedImage upright = rotate.apply(photo);
 Function<BufferedImage, BufferedImage> mirror = BufferedImageTransform.flipHorizontal();
 BufferedImage mirrored = mirror.apply(portrait);

a function that extracts the requested region

Returns a function that extracts a rectangle from an image as a new image.

The region is copied rather than viewed, so the result shares no raster with the source. That matters here: BufferedImage#getSubimage hands back a view onto the parent, which keeps the whole parent alive and leaves the copy off the plain image types the encoders expect.
