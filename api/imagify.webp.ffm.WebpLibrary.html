imagify.webp.ffm

WebpLibrary

FFM binding for the C ABI in src/main/native/webp/imagify_webp.h.

This is the Foreign Function & Memory API (JEP 454) counterpart to the JNA binding. It describes the function signatures and structure layouts needed to call the native libwebp-based shared library through Java's standard java.lang.foreign API.

See WebpCodec for how the native library is loaded and called.

LIBRARY_NAMEString

Name of the shared library as this jar builds it.

Deliberately not webp. libwebp builds libwebp.so, which is also the name of every system libwebp on Linux, so two of those can end up mapped in one process. This jar has no reason to interoperate with a system libwebp, so the library it publishes is given a name of its own.

ABI_VERSIONString

The version of the C ABI this binding was written against, as IMAGIFY_WEBP_ABI_VERSION in src/main/native/webp/imagify_webp.h spells it.

WebpLibrary(SymbolLookuplookup)

SymbolLookuplookup

a symbol lookup that can resolve the imagify_webp_* symbols

Creates a new FFM binding for the native library identified by lookup.

The caller is responsible for ensuring the library is already loaded (via System#load(String) or System#loadLibrary(String)) so that its symbols are visible to the default symbol lookup.

hasArgbEntryPoints()boolean

boolean true when the direct word entry points can be called

Whether the loaded library has the entry points that read and write 0xAARRGGBB words directly, which is what lets an image already in that layout be encoded and a decoded one be wrapped without a shuffle of the pixels in between.

All three or none: they were added to the header together and the export list lists them together, so a library that has two of them is not one this binding knows how to talk to, and treating it as though it has none is the answer that still works.

hasBgrEntryPoint()boolean

boolean true when #imagify_webp_encode_bgr can be called

Whether the loaded library has the BGR byte encode entry point.
