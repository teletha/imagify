imagify

Imagify

Fluent pipeline API for image processing.

Supports chaining: read → resize → write.

ImageReader#read always returns a FrameSequence, which may contain a single frame (for JPEG, PNG, etc.) or multiple frames (for animated formats like GIF and animated WebP).

Writing automatically detects whether the data is animated and the target format supports animation: if both conditions are met, the output is an animated image; otherwise the first frame is written as a still image.

Usage: 


 // Read → Resize → Write to file
 Imagify
     .read(path)
     .resize(800, 600, ResizeAlgorithm.LANCZOS3)
     .writeTo(path);

// Read → Resize → Write to bytes
byte[] png = Imagify
.read(bytes)
.resize(0.5)
.writeToBytes(ImageFormat.PNG);
// Keep the aspect ratio, cropping whatever overflows the box
Imagify.read(path).resizeToFill(1200, 630).writeTo(hero);
// Keep the aspect ratio, padding instead of cropping
Imagify.read(path).padTo(1200, 630, Color.WHITE).writeTo(hero);
// Take the poster frame of an animation
Imagify.read(gif).toStillImage().writeTo(poster);
// Get the first frame as a BufferedImage
BufferedImage img = Imagify.read(path).toBufferedImage();

Every transform applies to all frames of a sequence and leaves its timing alone. The resizing methods come in pairs that differ in what they do with a shape that does not match the target: #resize stretches to fit exactly, #resizeToFit and #resizeInside keep the aspect ratio and leave the result smaller than the target, #resizeToFill keeps it exact by cropping the overflow, and #padTo keeps it exact by adding the missing area.

resize(doublescale)Imagify

doublescale

the factor to multiply both edges by
Imagify

this pipeline, so the calls chain

Resizes by scale factor.

The factor applies to both edges, so the aspect ratio survives it. A value above 1 enlarges and a value below 1 shrinks; the target is rounded to the nearest whole pixel, which is the step that decides how far the result is from the exact multiple.

resizeToFit(intmaxDimension)Imagify

intmaxDimension

the length in pixels the longer edge is brought to
Imagify

this pipeline, so the calls chain

Resizes so that the longest edge becomes maxDimension, keeping the aspect ratio.

The result is at most maxDimension on both edges. A source smaller than maxDimension is scaled up, which is what the single argument ImageResizer#resizeToFit(BufferedImage, int) does as well; use #resize when only shrinking is wanted.

resizeInside(inttargetW, inttargetH)Imagify

inttargetW

the width of the box to fit inside
inttargetH

the height of the box to fit inside
Imagify

this pipeline, so the calls chain

Scales down to the largest size that fits inside the given box, keeping the aspect ratio.

Unlike #resizeToFill(int, int) nothing is cropped and no padding is added, so the result is smaller than the box on at least one edge whenever the source is not exactly the shape of the box. A source already smaller than the box is left at its own size rather than scaled up.

resizeToFill(inttargetW, inttargetH)Imagify

inttargetW

the width of the result, which is exactly this many pixels
inttargetH

the height of the result, which is exactly this many pixels
Imagify

this pipeline, so the calls chain

Scales and centre crops so the result is exactly the given size, filling the box completely.

The aspect ratio is not preserved: whatever the crop takes off is lost. This is the shape most callers mean by "make it 800 by 600" and is the counterpart of #padTo(int, int), which keeps the aspect ratio and adds the missing area instead.

inttargetW

the height of the canvas, which is exactly this many pixels

Scales to fit inside the given box and centres the result on a canvas of exactly that size.

The area the image does not cover is left fully transparent, since the canvas is BufferedImage#TYPE_INT_ARGB. Pass a colour to #padTo(int, int, Color) to fill it instead.

asSpriteSheet(ConsumerSpriteSheetlayout)Imagify

ConsumerSpriteSheetlayout

configures the grid, the cells, the spacing and so on
Imagify

this pipeline for chaining

Lays out all frames on a sprite sheet, turning the sequence into a single image.

The timing of the sequence is dropped, since a sheet has no notion of it. A still image becomes a sheet of one cell. To learn where each frame ended up, build the sheet with SpriteSheet directly and ask it for its layout.

asAnimation(intcolumns, introws, intdelayMs)Imagify

intcolumns

introws

intdelayMs

Imagify

this pipeline for chaining

Cuts the image into an even grid and makes every piece a frame of an animation.

Pieces are taken row by row. When the image does not divide evenly, the remainder on the right and bottom edges is dropped. The counterpart of #asSpriteSheet(int) for sheets without padding or spacing.

This undoes a sheet with padding and spacing exactly. Every frame is a whole cell, so a frame that was smaller than its cell comes back with the surrounding area attached.

toStillImage()Imagify

Imagify

this pipeline for chaining

Drops every frame except the first one, turning an animation into a still image.

Without this, writing an animation to a format that supports animation produces an animation even when only one frame is wanted. Chaining this first forces the result down to a single frame.

Usage: 


 // Take the poster frame of an animated GIF
 Imagify.read(path).toStillImage().writeTo(posterPath);
