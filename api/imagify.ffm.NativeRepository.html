Imagify

imagify.ffm

NativeRepository

Resolves the shared library that backs an AVIF, WebP or JPEG codec, fetching it from a GitHub release the first time it is needed.

The libraries do not ship inside the jar. Each of the three formats is published as its own release, one release per native version, with the six files of the six supported platforms attached. The runtime only ever wants one of the six, so fetching on first use is the whole point of the arrangement: what a user downloads is the file for their platform, not a jar with fifty megabytes of libraries for platforms they will never run on.

The tag that names the release is the only thing the jar knows about a library. It is written into imagify/<format>/native/native.properties beside the codec that needs it, and the natives workflow that builds and publishes the libraries reads the very same file, so the two cannot drift apart. The tag is immutable: publishing the same tag twice is refused on purpose, because a client caches what it downloaded for a tag and would have no way to learn that the file changed. A rebuild of the same native version is published under the same tag plus a dash suffix instead, and the suffix is added to native.properties in the same commit.

Resolution never throws and never blocks a codec. Every way of giving up records a reason, #lastReason(NativeCodec) reports it and returns null, and the codec falls back to a library installed on the system or reports the reason. The cache deliberately has no checksum verification: a release is immutable, so a file that sits where the cache expects it is known to be exactly what was published. Delete the cache directory to drop it and fetch again.

resolve(NativeCodeccodec)Path

NativeCodeccodec

the format whose library is wanted
Path

the absolute path of the library, or null when it could not be resolved, in which case #lastReason(NativeCodec) says why

Resolves the managed library of a codec, downloading it when it is not in the cache yet.

The resolution order is: an explicitly named library wins over everything; then the cache, keyed by (codec, tag, file name); then a download from /<tag>/<file>. Anything that gives up leaves a reason #lastReason(NativeCodec) reports, and the caller is free to fall back to a library the system provides.

tag(NativeCodeccodec)String

NativeCodeccodec

the format whose release is wanted
String

the tag, or null when the properties are missing or hold no tag

Reads the tag that names the release a format's libraries are published under.

The value lives in imagify/<format>/native/native.properties inside the jar, and the natives workflow reads the same file when it publishes, so the tag the runtime fetches is exactly the tag the workflow published.

cacheDirectory()Path

Path

the absolute cache directory

The directory downloaded libraries are kept in.

It defaults to ~/.imagify/natives and is moved with -D#PROPERTY_CACHE. The layout below the root is <format>/<tag>/<file name>, so the key of the cache is the release tag and the file name, and deleting the directory is the way to fetch everything again.
