ImageFormat.Webp

  • ImageFormat

WebP format (.webp). Lossy/lossless. Alpha support. Magic bytes: "RIFF...." + "WEBP"

WebP is the one format that comes in more than one flavour: #WEBP is the lossy VP8 bitstream and #lossless() the lossless VP8L one. They are separate values because the choice belongs to the encoder, and because a caller that has just read a file back wants to write it in the flavour it was read in: #fromHeader(byte[]) answers with whichever of the two the bytes say, so a file that survives a read and a write still holds every pixel it held before.

A flavour is a value rather than a constant, because a format may well come to carry more settings than this one, and a value that answers to its settings is the one that can. Two flavours holding the same settings are equal without being the same object.

The encoder has settings of its own besides the flavour, and the ones worth choosing are carried here too: #compressionMethod, how hard the encoder tries, and #allowMixed, whether it may store some frames without loss and others with loss. Both belong to an animation rather than to a single image, and the WebP binding this library uses wires only its animation encoder for them, so they say nothing about a still image.

DEFAULT_COMPRESSION_METHODint

The effort the encoder puts in when the format does not name one, which is what libwebp and the gif2webp tool use.

DEFAULT_ALLOW_MIXEDboolean

Whether the encoder may choose per frame when the format does not say, which is false: every frame is then stored in the flavour #lossless names.

losslessboolean

Whether the pixels are stored without loss, which also means the quality is ignored.

compressionMethodint

How hard the encoder tries, 0 being the quickest and 6 the most thorough.

More effort buys a smaller file for the same quality at the cost of a slower encode. This is libwebp's method, and it is honoured for an animation; the binding this library uses does not offer it to its single image encoder, so a still image is always written at #DEFAULT_COMPRESSION_METHOD.

allowMixedboolean

Whether the encoder may store some frames of an animation without loss and others with loss, choosing per frame instead of following #lossless for all of them.

This is what gif2webp calls -mixed: a frame that does not change is stored losslessly and the ones that do are stored lossily, which is a smaller file than storing every frame losslessly. A single image has no such choice to make.
