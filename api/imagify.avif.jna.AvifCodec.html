imagify.avif.jna

AvifCodec

Entry point to the libavif based AVIF codec.

The native library is loaded lazily, on first use, and failing to load it is never fatal: the ImageIO service providers of this library then stay inert instead of breaking ImageIO for every other format. Use #isAvailable() to find out.

Prebuilt shared libraries for Windows, macOS and Linux, in both 64 bit flavours, ship inside this jar and are unpacked on demand, so installing anything is not required. Should this jar hold no library for the current platform, a libavif found the usual way is used instead: point the jna.library.path system property (or the platform specific PATH / LD_LIBRARY_PATH) at the directory that holds it. 

 java -Djna.library.path=/usr/local/lib -cp ... YourApp

Set -Dimagify.avif.bundled=false to ignore the bundled library and always look for one installed on the system.

Supported libavif versions: 1.0.0 up to and including 1.4.x.

Decodes an AVIF file.

The pixels are always delivered as a BufferedImage#TYPE_4BYTE_ABGR image, whose banks are the very A, B, G, R layout libavif fills in for AVIF_RGB_FORMAT_ABGR. The alpha channel is fully opaque when the file carries no alpha.

isAvif(bytedata)boolean

bytedata

the leading bytes of a file, at least 12 of them
boolean true when the data looks like an AVIF file

Tests whether the given bytes are an AVIF file by looking for the avif or avis brand in the leading ftyp box.

The check is pure Java and therefore also works when the native library is missing, which lets ImageIO still recognise AVIF files.
