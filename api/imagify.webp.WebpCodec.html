imagify.webp

WebpCodec

WebP encoding and decoding, delegated to libwebp through webp4j.

This class is the single place that knows the third party API. Everything above it works in terms of BufferedImage and 0..100 quality, and never in terms of the quirks of webp4j:

  • webp4j takes a BufferedImage and scales quality to 0..100, while javax.imageio speaks in 0.0..1.0, so the conversion lives in the writer.
  • webp4j decodes animated files only through a separate entry point; its single image decodeImage fails outright on an animation. Both paths are reachable from here.
  • web4j wraps a decoded still image in a custom colour model rather than one of the standard BufferedImage types, so the result is normalised before it is handed out.

Images are always converted to a layout libwebp can import directly, and always through getRGB()/setRGB(), so an unassociated alpha channel survives without being premultiplied against an opaque background.

Reads the container headers of a WebP file without decoding the pixels.

For an animation the frame count and the loop count come from the animation decoder, because the still image headers do not carry them. That makes this call as expensive as decoding an animation, so the ImageIO reader calls it once and caches the answer.

Reports which of the two bitstreams a WebP file stores its pixels in, from the container alone.

A still image names its bitstream in the first chunk of the file, VP8L when it is lossless and VP8 when it is lossy. An animation is an extended file whose frames carry a bitstream of their own, so the first frame is the one that is looked at; a file that mixes the two is reported as its first frame has it. A container that says neither before the data runs out is reported as lossy, which is what #FORMAT_VP8L is not.

Unlike #readHeader(byte[]) this needs no native library and decodes nothing, which is what makes it usable while only a format is being detected, before any pixel has been looked at. Only the first #losslessHeaderLength() bytes are read, so a caller that has a shorter prefix than that is answered from what it has.

Reads a WebP file and decodes its frames in one pass.

Prefer this over #readHeader(byte[]) followed by a decode when the frames are wanted anyway, which is the case for every ImageIO read. #readHeader(byte[]) stays the cheaper choice for a still image inspected for its size alone, because it decodes no pixels.
