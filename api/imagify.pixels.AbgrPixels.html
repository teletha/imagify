imagify.pixels

AbgrPixels

Moves pixels between BufferedImage and the tightly packed A, B, G, R byte order this library's native codecs want on both sides of the boundary.

That byte order is what libavif calls AVIF_RGB_FORMAT_ABGR, what the jpegli shim in src/main/native/imagify_jpegli.c is given, and what a BufferedImage#TYPE_4BYTE_ABGR raster holds in memory, so an image of that exact type can be handed to and from the native code without touching a single byte. The correspondence is worth stating because it is easy to assume the opposite: the raster declares band offsets of 3, 2, 1, 0, so the byte at offset 0 of a pixel really is its alpha, while Raster#getDataElements reports the very same sample as R, G, B, A. Reading that array as if it were the in-memory layout swaps red and blue in both directions without ever failing, and #toBufferedImage and #toAbgrBytes are therefore the only two places allowed to touch raw bytes.

It lives outside the codec packages so that both imagify.avif.jna.AvifCodec and imagify.jpeg.jna.JpegliCodec share one conversion rather than keeping two that are only ever going to disagree.

Every other layout is converted through the source ColorModel, which always yields unassociated alpha, so that no premultiplication ever happens.

Extracts a sub-sampled region of an image as tightly packed A, B, G, R bytes.

Sub sampling takes the top left pixel of each subX by subY block, which is what javax.imageio.ImageReadParam#getSourceXSubsampling() specifies.
